## Kontrak guard untuk E3-1 dan E4-2 (terverifikasi 2026-10-16 di preview Worker)

- Strategi sesi: JWT (`src/auth.ts:104`, `SESSION_MAX_AGE_SECONDS = 3600`). Cookie sesi `authjs.session-token` (http lokal) / `__Secure-authjs.session-token` (https produksi). Klaim `role` ditulis saat login via `callbacks.jwt`.
- `requireAdmin()` (`src/lib/auth-guard.ts:9-14`): `{ ok: true, userId }` bila sesi admin; `{ ok: false, status: 401 }` tanpa sesi; `{ ok: false, status: 403 }` sesi non-admin. `requireSessionUser()` untuk endpoint milik sesi (dipakai `GET /api/waitlist/status`).
- Proxy `src/proxy.ts`: verifikasi JWT langsung (bukan `auth(request)` — beta ini mengembalikan Response, bukan sesi). Anonim → `307 /admin/login`; JWT valid tapi `role !== "admin"` (termasuk pengunjung Google) → `307 /admin/login?error=AksesDitolak`; admin → `next`. Token kedaluwarsa/rusak → `307 /admin/login`.
- Wajib untuk E3-1/E4-2: panggil `requireAdmin()` di server SEBELUM mutasi/sign presigned URL (klaim token bisa basi bila role diubah setelah login); GET publik tanpa guard dan hanya item published. Bukti matriks 10/10 + form E2E 9/9: anonim 307, login benar/uppercase → admin, salah/tak-ada/OAuth-only → ditolak generik, visitor/tanpa-role/rusak → 307 tepat, `exp-iat = 3600`, logout → sesi null + 307.
